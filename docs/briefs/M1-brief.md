## Scope

1. **GameState skeleton (doc 04 §3.1)**: saveVersion, turn, phase
   ('playing'|'ended'), activePlayer, rng state, players as a `SortedMap<
   PlayerId, Player>` wrapper (thin over Map, ascending-ID iteration for keys
   and values, serializable form), nextIds. Branded ID helper generic
   (PlayerId now; UnitId/CityId/TileIndex one-liners later). Map/units/cities
   placeholders. Player = {id, name}.
2. **Command registry** replacing the EndTurn if-chain: handler map keyed by
   cmd.type, entries {validate(state,cmd) → RuleViolation|null,
   apply(state,cmd,rng) → GameEvent[]}. EndTurn only registered command
   (advance activePlayer in sorted order, increment turn on wrap, draw from
   'turn' substream). Unknown command → RuleViolation from missing entry.
   Event union skeleton: TurnEnded.
3. **Save/load (doc 04 §3.4)**: SaveGame {saveVersion, engineVersion,
   contentHash (placeholder constant, documented), seed, snapshot,
   commandLog, turnHashes}. Game records executed commands + per-EndTurn
   hashes. snapshot() → SaveGame; Game.load(save) fast path;
   Game.replay(seed, commandLog) verification path.
4. **Migration framework v0**: serialize/migrations/index.ts, ordered
   Array<(raw:unknown)=>unknown> (index N: version N→N+1; empty at v0), load
   runs chain then hand-rolled structural validation (no zod in engine —
   zero-dependency). saveVersion > current → clear error.
5. **fast-check property tests** (fast-check@^4 devDep of engine, imported
   only from test/): replay identity (arbitrary seed, 0..50 EndTurns, run
   twice ⇒ identical hash chains, 500 runs); save/load transparency (N cmds,
   snapshot, load, M more on both ⇒ identical, 200+ runs); canonical
   round-trip + key-order independence; SortedMap order invariance under
   arbitrary insertion orders.
6. **Golden-log harness**: test-fixtures/golden-logs/ with 2 fixtures (seed,
   commandLog, expectedTurnHashes, expectedFinalHash), generated by root
   script `pnpm goldens:update`; vitest test replays fixtures;
   apps/cli/src/replay.ts verifies a fixture file, nonzero exit + clear
   message on mismatch.
7. **Shared turn-runner**: extract the run-N-EndTurns/hash-chain loop
   (duplicated in sim.ts and game.test.ts) into an engine-exported helper
   used by sim, tests, and goldens generation.
8. **docs/determinism.md**: contract — substream rules, integer-math rules,
   iteration-order rules, how property tests + goldens + CI double-run
   enforce it, goldens:update procedure.

Constraints (CI-enforced): engine zero runtime deps, no DOM/pixi/react; no
Math.random/Date.now/for...in/raw Object.keys in engine/ai src; integer math
only (Math.imul/>>>, no BigInt in hot paths); tsc strict green; existing
tests stay green (adapt for intentional API changes; sim final hash may
change — note it).

## Acceptance criteria (verify each, report honestly)

1. All property tests pass at stated run counts (pnpm test).
2. Save created mid-run, reloaded, replayed ⇒ matching hash chains
   (demonstrate with a concrete run, show hashes).
3. `pnpm run ci` fully green.
4. `pnpm sim -- --seed 1 --max-turns 10` twice ⇒ byte-identical (report new
   final hash).
5. replay CLI verifies a golden fixture; fails (nonzero, clear message) on a
   tampered expected hash — show both.
6. docs/determinism.md exists and matches implementation.
